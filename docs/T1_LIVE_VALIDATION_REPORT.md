## 2. 剧集内容摘要（直接依据真实剧本）

### EP01 — 请求排练
Joey 说试镜台词卡壳，向 Chandler 请求十分钟的排练帮助。Chandler 以延误的工作报告自嘲，并答应排练。Joey 说明试镜是一场「兄弟摊牌、其中一人要离开」的戏；两人最终开始准备。

### EP02 — 实际排练
Joey 从兄弟离别的场景对白开始，Chandler 在戏内回应。Joey 逐渐投入，之后跳出表演，表示 Chandler 的回应让自己接近落泪，希望再来一次；Chandler 继续用工作报告的压力作笑点，同时愿意合作。

**因果延续的正证据**：EP02 的「兄弟离开」戏码与 EP01 的具体排练内容相符，且 EP02 的 `prior_memory_ids` 确认输入侧收到了 EP01 的事件 ID。说明跨集**上下文注入正常**，实际产出也体现了与前情一致的话题接续。

**不能过度推断**：只有一次采样；未进行去掉记忆的对照；无法证明模型只因记忆而做出选择，更无法证明多集关系演化或稳定创作高质量情景喜剧。

## 3. 质量与产品目标的距离

| 维度 | 实证观察 | 判断 |
|---|---|---|
| 角色辨识 | Joey 热情、直接、投入表演；Chandler 用自嘲谈工作压力 | **初步可辨识**，但样本仅两集八句话 |
| 跨集上下文 | EP02 续演 EP01 明确提出的场景 | **初步通过** |
| 地点/事实 | 两集均在同一公寓、同一 evening 场景；对话事件有证据 | **本样本无明显冲突**，尚未实测移动和多人会面 |
| 内容可读性 | 对话自然、连贯，有轻松幽默片段 | **初步可读**，尚非 3–5 场的成熟剧集 |
| 关系因果 | 朋友帮助朋友的情节出现 | **没有量化或事件驱动的关系更新实现** |
| 角色自主生活 | 两集由固定 Joey/Chandler 顺序调用、固定场景和固定目标产生 | **未验证** |
| 用户追剧意愿 | 没有试读者测试；两集实质为一段排练的前后部分 | **未知** |

### 三个主要差距

1. **集数不等于不同虚拟日**：T1 每个 `next` 仅运行四次轮流决策，EP01 以「准备好了吗」收尾，EP02 直接接着排练。没有真正的虚拟日/时段/生活事件推进。不能将成功的连续对话当成完整情景喜剧世界。
2. **尚无关系演化**：本版本仅把目击对白存为独立记忆，没有结构化承诺、客观兑现或变化证据，也没有关系更新。
3. **行为自由度有限**：每集固定按 Joey→Chandler→Joey→Chandler 调用；可以返回 wait/move/do，但没有自主活动分配或社会性邀约，喜剧片段较为单一。

另一个较小的观察：文本里包含「深吸一口气」「忽然跳出角色」之类直接写在 `speak.text` 中的舞台动作。当前它们尚未经过独立的动作执行验证；后续需要区分舞台提示与世界事实，但不必为此引入新的 Agent 架构。

## 4. 阶段判断：T1 技术闭环通过，准许进入 T2 的最小故事闭环

**可以进入 T2**，条件是仍把产品价值作为优先目标，而不是铺设大规模基础设施。

优先级排序：

1. **P0：引入真正的场景推进**：从一段对话切分两个标题，升级为每次 `next` 产生一个具有起止边界的虚拟日；同一天可有多个基于实际会面的场景，而不规定必须发生冲突。
2. **P0：增加角色自主选择**：按当前目标、记忆、场景信息作活动意向选择，让角色有机会主动求助、拒绝、等待或离开；角色发言不必固定按名字轮流。第一步先小地图和少量会面即可。
3. **P0：让重要事件持续产生后果**：至少支持明确的承诺/履行及简单、有 event_id 证据的关系变化；仍区分双方主观认知。不要先加入复杂公式、向量记忆或关系网络分析。
4. **P0：拓展为六人单集**：沿用同一模型调用接口和持久化事务，先得到一个真实多角色剧本，不追求复杂 GUI。
5. **T3 再验证**：七集内容、至少三集的关系线、角色一致性、读者追剧意愿；达到前不得声称 Story Prototype 全部完成。

**明确非目标**：不在 T2 引入通用 Scheduler、管理型 Agent、复杂图数据库、精密情绪评分模型或视频前端。
