# FriendsVerse — 产品决策记录

**建立日期**：2026-10-23  
**原则**：本文件只记录**已经明确决定**的产品选择和未决议题，不把建议误写成承诺。

## 已确认（Accepted）

| ID | 决策 | 理由与产品影响 |
|---|---|---|
| D-001 | 产品以六个虚拟角色自主生活、持续发展关系为中心 | 用户主要希望欣赏故事、观察他们之间的关系 |
| D-002 | 故事风格为**轻松搞笑** | 以日常幽默与群像互动为优先，而非沉重剧情 |
| D-003 | 呈现形式为**情景剧剧本** | 以角色对白、必要动作和场景描述为主，避免第一版投入动画/视频 |
| D-004 | 世界按**用户手动逐集推进** | 观众主动控制追剧节奏，不要求实时后台模拟 |
| D-005 | 用户为**观众**，而非直接控制角色的玩家 | 以观看自主行为和关系变化为核心体验 |
| D-006 | 初期使用不超过十位角色，优先六位经典主角 | 降低角色关系组合和一致性维护复杂度 |

## 当前 PRD 中的方案建议（Proposed，未锁定）

- 每集暂按一个虚拟日推进，3–5 场、3–6 分钟阅读量。
- MVP 为单用户/单宇宙，三页面：大厅、阅读器、关系查看。
- 角色关系暂用亲密、信任、矛盾三个有向指标。
- 引入有限的生活事件池（只提供情境）和剧集整理器（只整理模拟事实）。
- 先做七集 Story Prototype，再投入完整 Web 产品。
- 借鉴 social-agent-sim 的 Tick/感知/动作执行，不预先确定 fork 或移植。

以上建议写在 PRD 里作为当前设计基线，可在下一次产品评审中修订。

## 未解决（Open）

1. 第一季是否固定年代、角色初始关系和居住位置，或者允许少量初始变体？
2. 短时间模拟中，如何平衡剧集趣味性、角色自主性与成本？
3. 关系指标是否完全量化，如何校准事件权重与可信度？
4. 是否先以命令行七集样本验证、再开发 Web？
5. 公共发行是否采用原创角色 IP，还是申请授权？
6. 采用何种运行模型、部署架构、持久化实现？
