# FriendsVerse — 产品需求文档（PRD）

**版本**：v0.7.0（实现进展与七集实验入口）  
**更新日期**：2026-10-24  
**状态**：T0/T1 技术链路完成；T2 六角色单日代码已自动验证；T3 七集工程验证和报告入口已开发，真实六角色/七集内容质量尚未验收  
**负责人视角**：产品与用户体验优先，暂不锁定技术框架

## 1. 产品概要

### 1.1 一句话定位
由六位拥有稳定人格、独立记忆和动态关系的虚拟角色自主生活，持续产生**轻松搞笑、有因果连续性的情景喜剧剧本**，让观众手动逐集追看人物关系的发展。

### 1.2 核心用户与待验证价值
目标用户：喜爱《老友记》式群像情景喜剧、关注人物友情与情感关系的观众。  
核心体验：**因为喜欢角色开始看，因为好奇关系如何发展而继续看。**  
待验证核心假设：观众愿意持续观看 AI 自主模拟产生、经事实约束编排的连续剧本。

### 1.3 已锁定的产品选择
- **风格**：轻松搞笑；日常误会、友情、温情与轻度感情线；不靠重度狗血强推剧情。
- **媒介**：情景剧剧本，展示地点、场景、人物动作、对白；MVP 不做视频或完整动画。
- **推进**：用户点击「生成下一集」才推进世界；每集按一个虚拟日组织模拟，平淡片段可跳过。
- **参与**：观众模式，不直接操纵人物、不投放事件；系统可提供有限的生活事件。
- **角色**：初期六位主角，后续关系发展不受原剧固定剧情约束；不强制所有人每集出场。
- **叙事真实性**：Agent 行动与世界事件先发生，剧集整理器随后编排；不可凭空创作未发生的动作、对白或关系变动。
- **初期范围**：单用户、单宇宙优先，默认角色与初始场景；暂不设计社交平台。

## 2. 产品原则和非目标

1. **角色优先**：人格稳定但心情、观点与关系可随经历变化。
2. **因果优先**：每项重要关系变化可追溯到具体模拟事件。
3. **知识隔离**：角色只知道自己观察到、听到或被告知的事；观众不能无故获知角色秘密。
4. **自主优先**：环境事件只提供机会，不预先指定角色反应和结果。
5. **阅读体验优先**：尽量省略无趣日常，不把全部 Agent 日志展示为剧本。
6. **控制成本和复杂度**：不为常规通勤、睡眠等重复活动做无谓模型调用。

不做：实时开放世界游戏、多人在线社交、角色对话机器人、完整 2D/3D 游戏、语音与 AI 视频、复杂经济系统、重型 RPG 规则、预设每集剧本。

## 3. 核心用户旅程

### 3.1 新用户
进入首页 → 一键「开启新宇宙」 → 初始化六个人格与关系、社区和事件状态 → 生成 EP01 → 阅读 → 查看本集关系变化 → 自愿生成 EP02。

### 3.2 追剧用户
返回首页 → 查看最新集和已读进度 → 阅读或生成下一集 → 查看人物关系与前情 → 继续观看。已发布的集数及世界历史保持稳定，不因重新打开而重生成。

### 3.3 关系观察者
进入人物关系页 → 选择 A→B → 查看亲密、信任和矛盾的当前状态 → 查看关系变化的证据事件 → 跳转对应剧集和场景 → 返回最新剧集。

### 3.4 失败恢复
点击生成 → 显示进行中、禁止重复触发 → 若失败，保持上一集与已提交世界状态完整、允许重试 → 成功后原子性地发布新剧集与状态版本；不可重复追加同一集。

## 4. 信息架构与页面

### P0：剧集大厅
- 最新一集：集数、标题、导语、主要人物；「阅读」「生成下一集」。
- 剧集列表、上次阅读位置、前情摘要。
- 初始空状态：一键开启默认宇宙。
- 生成中 / 失败 / 完成状态，明确向用户反馈。

### P0：剧集阅读器
- 逐场阅读：场景编号、地点、时间、人物动作与对白。
- 上一集、下一集、返回目录；简短前情。
- 每集结束展示本集重要事件和主要关系变化（不揭示未公开秘密）。
- 既有集数内容固定，并可回溯每段故事的模拟来源。

### P0：人物关系
- 六人基本信息和关系浏览。
- 每个有向关系显示：Closeness、Trust、Tension；范围可暂用 0–100。
- 显示当前关键关系事件、变化依据及剧集链接。
- 不将数值简单等同于「喜欢/讨厌」，关系方向可不对称。

### P1：后续增强
关系曲线、角色个人日记、跨季总结、平行宇宙、剧集分享。

### 5.1 人物模型（产品语义）

六位角色的完整 Persona、初始社会事实、15 组有向关系视角与验证情境详见 **[Character Design：六人角色与初始关系](CHARACTER_DESIGN.md)**。该方案处于待验证状态，不代表角色权重或未来情节已经确定。

六位主要人物：Monica、Rachel、Phoebe、Ross、Chandler、Joey。每人具有：
- **稳定 Persona**：价值观、表达方式、弱点、长期追求。
- **动态状态**：心情、位置、当前任务、短期目标。
- **个人记忆**：经历、承诺、未解矛盾、对他人的主观印象。
- **社交关系**：A 对 B 的亲密度、信任度、矛盾度，附证据事件。

注意：这描述的是产品数据需求，不意味着采用单一量化公式或指定数据库；参数如何校准尚待实验。

### 5.2 社区与世界

社区地点、三个虚拟时段、角色活动意向、社交触发、会面解析、对话终止、信息隔离和具体验收情境详见 **[World & Interaction Design](WORLD_INTERACTION.md)**。这是一版待验证的产品机制，不代表模型调用预算和实现细节已经锁定。

初版建议以两套主要公寓、走廊、Central Perk 和可抽象表示的其他住处为主。角色可以共处、相遇、交谈、移动、等待；常规生活行为可按规则推进。地点、可见性、行动条件与事件触发需要一致。

### 5.3 剧集格式
- 建议每集 **3–6 分钟阅读量**、约 **3–5 场**，允许随内容质量浮动。
- 通常一条主要人物关系线，可有轻量支线。
- 场景要有地点/时间、必要动作、对白，避免冗长旁白。
- 不要求每集都有高潮、反转或悬念；重要的是自然的情景喜剧体验。
- 应有明显的角色差异和轻松笑点，但不能为搞笑篡改真实模拟事实。
- 人工观看时可以从对白区别角色，不强制复制经典台词。

### 5.4 生活事件示例
Joey 的试镜、Monica 的晚宴、咖啡馆设施损坏、寄错快递、Rachel 的职业选择。事件定义**前提条件和环境变化**，而非角色必须说什么、吵架与否、最后怎样和解。

### 5.5 剧集生成链
世界状态 → 局部感知 → Character Agent 结构化动作 → 行动规则校验/执行 → 事件与角色记忆更新 → 关系变化记录（含证据） → 从日志选择可读场景 → 事实一致性检查 → 发布剧集与世界快照。

剧集整理器是「剪辑师」，不是可以独立改写世界的「编剧」。对模型生成的关系解释应保留来源和必要的人工审查空间。

## 6. Story Prototype 验收（首个里程碑）

工程实现的推荐模块、领域数据、生成事务/失败恢复、模型调用和 T0–T3 分阶段验收见 **[Story Prototype Technical Design](STORY_PROTOTYPE_TECHNICAL_DESIGN.md)**。Python/SQLite 等是当前候选实现，不代表产品层已锁定永久技术栈。


详细角色基线、故事机会池、关系演化、单集生成契约、七集实验安排和 Go/No-Go 标准见 **[Story Prototype 详细产品规格](STORY_PROTOTYPE.md)**。本节是简明验收摘要；详细的原型行为以该规格说明为准，不意味着已决定底层技术选型。

**测试目标：连续运行一个虚拟星期并得到七集有关联的剧本。**

当前已实现专用 [T3 七集实验](T3_SEVEN_EPISODE_EXPERIMENT.md) CLI、可恢复的逐集提交以及原始剧本和事件证据导出。工程运行通过不代表故事连续性、幽默感或观众体验已经通过。

基本检查：
1. 七集可读、稳定保存、顺序正确。
2. 六人的身份与基础表达方式可区分，无明显人格漂移。
3. 至少存在一条持续三集以上、具备事件证据的关系发展线。
4. 历史承诺、误会和关键关系跨集延续；无明显信息穿越。
5. 关系状态和剧本可追溯到模拟日志。
6. 邀请 3–5 位观众试读，分别按 1–5 分评价：角色辨识、幽默感、连贯性、关系可信度和追剧意愿。

**核心评估问题**：观众是否愿意立即生成/阅读下一集？首先以定性反馈定位问题，不以小样本推断广泛留存率。

## 8. 风险与对策

- **平淡流水账**：提供非强制的日常事件与基于事实的片段筛选；用实际试读检验效果。
- **人格漂移**：稳定 Persona + 动态状态分离；人工角色辨识评测。
- **关系虚假突变**：变化绑定原始事件；禁止无依据的大幅波动。
- **记忆与全知问题**：独立记忆、局部感知、信息传播链可追溯。
- **Token/运行成本**：常规动作由规则处理；只对有意义交互调用模型；具体预算另行实验。
- **著作权/商标/肖像**：私人粉丝实验与面向公众发行需区别对待；公开产品需授权或原创 IP。
