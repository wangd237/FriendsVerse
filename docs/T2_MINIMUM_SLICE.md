# T2 — 六角色端到端最小闭环

**设计方向**：横向打通六角色、世界推进、主动决策、社会动作、证据关系和剧本持久化；不为局部优化停留。

## 代码范围

- `python -m friendsverse init --mode ensemble` 创建六人世界和有向关系。
- `python -m friendsverse next --provider live` 推进一个虚拟日，按上午/下午/晚上分别生成意向和现场回应。
- 模型基于本人的 Persona、目标、记忆、自己的关系和实际现场进行决策。只有双方同处现场才能听见对白或执行社会动作。
- 小型真实环境刺激提供客观生活机会，没有指定任何台词/吵架结局。
- 动作经过世界规则，帮助、道歉、分享、承诺和兑现产生事件；只有完成的实际行为能引起有来源的关系变化。
- 事件逐条记录，简单剧本按事件位置与时间顺序呈现，不捏造未执行的对白。
- SQLite 单事务提交完整世界状态和剧集，可连续推进至 Day 2+。
- `EnsembleFakeClient` 只为 CI 测试整个数据闭环；评价故事需要运行真正的 `T2 ensemble live smoke (manual)`。

## 不扩展范围

当前内容侧是日志式情景剧而非成熟编辑器；没有全局计划编剧、向量记忆或多 Agent 主管。活动意向来自角色但尚未有真实日程/通勤系统。关系更新使用非常小的事件驱动增量，不假装具有精确心理学意义。**六人模式能跑通不等于剧本质量合格。**

## T2 验收步骤

1. CI：T0/T1 回归与六人 Fake 两日流程均通过。
2. 手动运行 `T2 ensemble live smoke (manual)`，检查六个人是否有实际可读互动、是否存在被拒动作、是否有虚假关系变化。
3. 下载 `t2-ensemble-review` 中的剧本、事件及关系变化，按角色辨识、剧情连续、幽默、节奏做全链路审查。
4. 有关键工程缺陷时按影响程度修复，然后进入 T3 七天实验；不在语言风格、具体地点等小细节无限打磨。
